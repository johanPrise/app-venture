# App Venture

App Venture is a platform for discovering, sharing and supporting startup pitches. Entrepreneurs sign in with GitHub, publish a pitch, and the community browses, searches and votes for the ideas they like.

## Features

- **GitHub sign-in** with NextAuth v5 (Auth.js). An `author` document is created in Sanity on first sign-in.
- **Pitch creation**: title, description, category, image URL and a Markdown pitch. The form is validated with Zod both in the browser and in the server action.
- **Search** by title, category or author name.
- **Sorting** on the home page: most recent (default) or most voted (`/?sort=votes`).
- **Votes**: one vote per user and per pitch, toggled from the pitch page with an optimistic update.
- **View counter**: counts at most one view per visitor, per pitch, every 24 hours. Bots and the pitch author are not counted.
- **Author profiles** listing each author's pitches.
- **Editor picks** shown on each pitch page, curated in Sanity with a playlist.
- **Embedded Sanity Studio** at `/studio`.
- **Error monitoring** with Sentry.

```
    user/[id]/             Author profile

  studio/[[...tool]]/      Embedded Sanity Studio

  action.ts                Server actions: createPitch, toggleVote, incrementView, signInToVote
  validation.ts            Zod schema for the pitch form
sanity/
  schemaTypes/             Content model: author, startup, playlist, vote
  lib/queries.ts           GROQ queries
  lib/client.ts            Read client
  lib/write-client.ts      Write client (server only, requires a write token)
  types.ts, extract.json   Generated by the Sanity typegen
auth.ts                    NextAuth configuration
```

## Content model

| Type | Purpose |
|---|---|
| `author` | A user, created on first GitHub sign-in (`id` is the GitHub user id). |
| `startup` | A pitch. Holds `title`, `slug`, `description`, `category`, `image`, `pitch` (Markdown), `views`, and a reference to its `author`. |
| `playlist` | A curated list of startups. The pitch page displays the playlist with slug `editor-picks-new` as "Editor Picks". |
| `vote` | A reference to an `author` and a `startup`. Its `_id` is always `vote-{startupId}-{authorId}`. |

Vote uniqueness relies on that deterministic `_id`. Sanity allows only one document per `_id`, so a user can never hold two votes for the same pitch. Votes are created with `createIfNotExists`, which makes a double click harmless. The author id always comes from the server-side session.

## Getting started

### Prerequisites

- **Node.js 22 LTS.** With newer releases (Node 26), the Sanity CLI used by `npm run typegen` currently crashes.
- A Sanity project with a dataset.
- A GitHub OAuth App.

### 1. Install

```bash
npm install
```

### 2. Configure environment variables

Create a `.env.local` file at the project root. It is ignored by git.

```bash
# Sanity
NEXT_PUBLIC_SANITY_PROJECT_ID=your-project-id
NEXT_PUBLIC_SANITY_DATASET=production
NEXT_PUBLIC_SANITY_API_VERSION=2025-01-19   # optional, defaults to 2025-01-19
SANITY_WRITE_TOKEN=                         # Editor token: creates authors, pitches, votes, views
SANITY_API_TOKEN=                           # optional, read token for the read client
SANITY_SERVER_TOKEN=                        # Viewer token for the Live Content API (server)
NEXT_PUBLIC_SANITY_TOKEN=                   # Viewer token for live updates in the browser (exposed to the client)

# NextAuth / GitHub
AUTH_GITHUB_ID=
AUTH_GITHUB_SECRET=
NEXTAUTH_SECRET=                            # e.g. `npx auth secret` or `openssl rand -base64 32`
```

If the project is linked to Vercel, `vercel env pull .env.local` downloads these values.

Create the Sanity tokens in [sanity.io/manage](https://www.sanity.io/manage) → your project → API → Tokens. Only `NEXT_PUBLIC_SANITY_TOKEN` reaches the browser, so give it read-only (Viewer) permissions.

### 3. Create the GitHub OAuth App

In GitHub → Settings → Developer settings → OAuth Apps, set the **Authorization callback URL** to:

```
http://localhost:3000/api/auth/callback/github
```

A GitHub OAuth App accepts a single callback URL. Use one OAuth App for local development and another for production (`https://<your-domain>/api/auth/callback/github`). Otherwise GitHub rejects the sign-in with *"The redirect_uri is not associated with this application"*.

### 4. Allow the local origin in Sanity

In [sanity.io/manage](https://www.sanity.io/manage) → API → CORS origins, add `http://localhost:3000` with credentials allowed. This is required for the embedded Studio and live updates.

### 5. Run

```bash
npm run dev
```

Open [http://localhost:3000](http://localhost:3000). The Studio is available at [http://localhost:3000/studio](http://localhost:3000/studio).

## Scripts

| Command | Description |
|---|---|
| `npm run dev` | Runs `typegen`, then starts the dev server (Turbopack). |
| `npm run build` | Runs `typegen`, then builds for production. Type errors and ESLint errors fail the build. |
| `npm run start` | Serves the production build. |
| `npm run lint` | Runs ESLint through `next lint`. |
| `npm run typegen` | Extracts the Sanity schema to `sanity/extract.json` and generates `sanity/types.ts`. |

Run `npm run typegen` after changing anything in `sanity/schemaTypes/`, and commit both generated files.

## Deployment

The app is deployed on Vercel:

1. Add all the environment variables above in the Vercel project settings.
2. Add the production domain to the Sanity CORS origins.
3. Point the production GitHub OAuth App callback URL to `https://<your-domain>/api/auth/callback/github`.
4. Optional: set `SENTRY_AUTH_TOKEN` to create Sentry releases and upload source maps during the build. The Sentry org and project are configured in `next.config.ts`.

Preview deployments get a new URL for each deployment. GitHub sign-in only works on them if the preview URL is registered in a GitHub OAuth App.
